# 데이터 수집 과정에서 다룬 문제

이 프로젝트에서는 급등 종목을 탐색하는 로직뿐 아니라, 장시간 실시간 데이터를 수집하는 과정에서 발생하는 지연·누락·중복·세션 경계 문제를 함께 다루고 있습니다.

실시간 시장 데이터는 항상 원하는 시점에 완전한 형태로 제공된다고 가정하지 않고, 수집 과정에서 발생한 상태를 가능한 한 구분해서 기록하는 방향으로 개발하고 있습니다.

## API 요청 제한과 작업 순서

후보 종목 탐색과 관측 이후 가격 추적을 동시에 수행하면 API 요청이 특정 시간대에 집중될 수 있습니다.

후속 가격 조회가 길어지면서 다음 Feature 관측 시점까지 밀리는 문제를 줄이기 위해 요청 간격과 작업 시간 예산을 관리하고, 우선순위가 낮은 작업은 다음 주기로 넘길 수 있도록 구성했습니다.

HTTP 429나 일시적인 네트워크 오류가 발생하는 경우에는 제한적으로 재시도하며, 특정 종목의 조회 실패가 전체 수집 프로세스를 중단시키지 않도록 개별적으로 처리합니다.

프로그램의 목적은 모든 API 요청을 반드시 한 번에 완료하는 것이 아니라, 핵심 관측 주기를 가능한 한 유지하면서 실패한 후속 작업을 별도로 관리하는 것입니다.

## 오래된 데이터와 조회 실패 구분

API에서 가격이 반환됐다는 이유만으로 해당 데이터를 항상 정상 관측으로 사용하지 않습니다.

거래가 활발하지 않은 종목이나 일시적인 데이터 지연으로 최신 분봉이 실제 관측 시점보다 오래된 경우가 있기 때문에, 최신 봉의 시각을 함께 확인하고 일정 범위를 벗어난 데이터는 별도로 제외합니다.

또한 다음과 같은 상태를 동일하게 처리하지 않도록 구분하고 있습니다.

- 정상적으로 관측된 데이터
- 최신 가격은 존재하지만 오래된 데이터
- API 요청 자체가 실패한 경우
- 필요한 과거 이력이 부족한 경우
- 중간 시계열이 누락된 경우

관측 실패를 가격 변화 0%와 동일하게 처리하면 연구 결과가 왜곡될 수 있기 때문에, 계산 가능한 데이터와 계산할 수 없는 데이터를 구분하는 것을 중요하게 보고 있습니다.

## 관측 시점 이후 가격 추적

특정 Feature가 기록된 뒤에는 여러 시간 간격의 후속 가격을 연결해 이후 움직임을 분석합니다.

이 과정에서는 목표 시간이 되었을 때 실제로 관측된 가격과, 목표 시간에 데이터가 존재하지 않는 경우를 구분합니다.

또한 세션 종료 이후까지 필요한 관측은 단순 누락으로 처리하지 않고, 해당 세션에서는 측정할 수 없는 데이터로 별도 관리합니다.

이를 통해 데이터가 존재하지 않는 이유와 실제 가격 움직임을 가능한 한 분리하려고 했습니다.

## PRE / REG 세션 경계

미국 주식의 프리마켓과 정규장은 거래 환경과 데이터 조건이 다르기 때문에 동일한 연속 시계열처럼 단순하게 처리하지 않습니다.

관측 시점과 목표 시점이 어느 세션에 속하는지 확인하고, 세션 종료를 넘어가는 후속 관측은 별도로 구분합니다.

초기 급등 종목의 경우 새 세션이 시작된 직후에는 현재 세션의 분봉 이력이 충분하지 않을 수 있기 때문에, 이전 거래일의 데이터가 존재한다는 이유만으로 현재 세션의 짧은 이력을 정상적인 3분 이력으로 판단하지 않도록 별도 검증 로직을 두고 있습니다.

## Early Burst 연구 트랙

일부 급등 종목은 프로그램이 처음 발견했을 때 이미 큰 폭으로 상승한 상태이며, 충분한 분 단위 과거 데이터가 존재하지 않을 수 있습니다.

이 경우 기존 분 단위 연구 트랙과 동일하게 처리하면 초기 움직임을 관측하기 어렵기 때문에 별도의 Early Burst 연구 트랙을 만들었습니다.

이 트랙은 분 단위 과거 이력이 부족한 종목을 별도로 식별한 뒤 WebSocket 기반 실시간 데이터를 이용해 짧은 시간 구간의 움직임을 기록하도록 설계했습니다.

현재는 짧은 시간 단위 snapshot과 MFE/MAE 기록 구조를 구현했으며, 실제 시장 환경에서 연결·구독·수신·저장 과정이 정상적으로 이어지는지 단계적으로 검증하고 있습니다.

## 재시작과 상태 보존

장시간 실행되는 프로그램에서는 네트워크 오류나 프로그램 재시작 가능성도 고려해야 했습니다.

일부 연구 데이터는 SQLite에 상태를 저장하고, 이미 처리한 종목과 관측 시점을 식별할 수 있도록 구성해 재시작 이후 동일한 신호나 결과가 반복 생성되는 것을 방지합니다.

CSV는 분석과 확인이 쉬운 출력 형식으로 사용하고, 상태 관리가 필요한 데이터는 별도의 저장 구조를 함께 활용하고 있습니다.

## 연구 데이터와 검증 데이터 분리

초기 데이터에서 발견한 조건을 같은 데이터에 반복적으로 적용하면 과최적화될 가능성이 있습니다.

따라서 연구 과정에서 만든 규칙을 일정 시점에 동결하고, 이후 새롭게 수집되는 거래일 데이터를 별도의 OOS(Out-of-Sample) 데이터로 사용해 검증하고 있습니다.

새로운 결과가 좋거나 나쁘다는 이유만으로 기존 규칙을 즉시 변경하지 않고, 충분한 표본을 확보한 뒤 별도의 연구 단계에서 다시 검토하는 방식을 사용하고 있습니다.

## 테스트와 검증

운영 프로젝트에서는 주요 데이터 처리 로직에 대해 unit test와 regression test를 작성해 수정 과정에서 기존 기능이 함께 변경되지 않는지 확인하고 있습니다.

특히 최근에는 다음과 같은 사례를 별도로 테스트하고 있습니다.

- 정상적인 짧은 세션 이력
- 중간 분봉 누락
- stale 또는 미래 시각 데이터
- 중복 또는 충돌하는 과거 봉
- API 및 네트워크 오류
- 정확한 과거 가격이 존재하는 경우와 존재하지 않는 경우
- 재시작 이후 중복 기록 방지

공개 저장소에는 실제 운영 코드와 전체 테스트를 포함하지 않으며, 합성 데이터를 이용한 독립적인 예제만 제공합니다.

따라서 공개 예제는 실제 연구 파이프라인 전체를 재현하는 것이 아니라, 데이터 유효성 검사와 중복 제거 등 프로젝트에서 사용하는 기본적인 처리 원칙을 보여주기 위한 예제입니다.

## 현재 한계

현재 수집된 가격 변화와 MFE/MAE는 시장 관측 결과이며 실제 주문 체결 수익률과 동일하지 않습니다.

아직 거래비용, 슬리피지, 주문 체결 가능성, 호가 유동성 등 실제 매매 과정의 요소를 충분히 반영하지 않았습니다.

또한 새로운 연구 트랙과 장애 복구 로직은 실제 시장 데이터를 계속 축적하면서 검증하고 있으며, 충분한 기간과 다양한 시장 환경에서 추가 검증이 필요합니다.
